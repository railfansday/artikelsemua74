Industry observers note that according to McKinsey’s latest State of AI survey, 44% of organizations that use AI say it’s now scaling across their enterprise, up from 38%. In many organizations, AI is still considered an experiment. But that doesn’t mean individual AI use hasn’t already become critical infrastructure, sometimes without leadership even realizing. Although that particular AI application wasn’t approved, it had already become part of the agency’s customer service workflow. As AI agents start running work on their own, such dependencies will only grow deeper. Banning AI isn’t realistic; instead, we must treat it as the business continuity concern it really is.

It has been revealed that organizations have spent two decades learning how to manage their reliance on cloud and SaaS providers. They can measure service availability, latency and other metrics, and create backups to prepare for possible outages.

AI introduces a less deterministic dependency. An AI service can stay online and keep returning answers after its behavior has changed. Dependent workflows can appear fine while producing less accurate or less complete results.

It has been revealed that in June 2026, a U.S. export-control directive led Anthropic to suspend Claude Fable 5 for all customers. When it returned in July, Anthropic said its new safety classifier would flag benign coding and debugging requests more often, possibly sending blocked requests to an older model. In August, Anthropic retrained Fable 5’s separate biology classifier, which sends flagged requests to yet another model. Within two months of launch, Fable 5 had been suspended, rerouted and retuned, all under the same model name. If an organization wasn’t evaluating its outputs with Fable, it wouldn’t understand how these changes affected its work.

Industry observers note that ​IT leaders need a proposal for what happens if a provider changes its model, performance falls below an acceptable level or prices fluctuate. Price can move in either direction; for example, in September, Anthropic noted its fresh Opus 5.5 model would cost about 40% less than its predecessor on typical workloads. If an organization doesn’t have the flexibility to switch models, it can’t take advantage of those savings.

A business continuity strategy should start by defining an acceptable level of model performance, which can’t be left to provider benchmarks. This plan should also include a test set of problems the organization has already solved and can use to measure model performance. Present each model with a problem, withhold the known answer, and score the result. These tests should determine:.

1. Did the AI model complete its task?

Sources indicate that 2. Was the result checked against an authoritative source the AI did not produce?

According to recent reports, 3. Does the model answer questions consistently, if asked multiple times?

4. What did each completed task cost?​​.

Run this test set any time a model changes. Without this internal baseline, an organization might sense that a service has become less reliable, but be unable to demonstrate any shift in behavior.

​An AI harness is often described as a layer that filters model inputs and outputs. I think about it differently: Picture a talented soccer player, alone with a ball on a planet covered in grass. His ball control is perfect, and he can run the ball around the planet endlessly. It is impressive, and it is pointless.​.

In a recent development, ​To make this a game, you need lines, goal posts, rules, referees, a scoreboard and a stadium. A harness is all of those things for AI. It gives the model a goal and defines what a successful output is. It determines which data and systems that AI may touch. It also keeps a record that helps organizations learn, as corrections and verified reference data stay in the harness, rather than in the model itself.

In a recent development, any soccer game requires an impartial referee. In my field, if an AI agent proposes a firewall change, then that proposed change must be checked against a model of network behavior that the agent did not build or edit. The system that validates a change should never be the system that made it.

Sources indicate that AI harnesses also ensure business continuity throughout times of change. On any soccer team, players can get injured or transferred, but the club keeps its stadium, its rules and its record. When my firm changed its AI subscription, I had AI rebuild my workflow setup into a portable harness in a folder I control. This harness also helps me to run the same tests across several models and pick the one that fits each workflow, rather than assuming the most expensive one is best.

You don’t need to own every data center or chip in your AI stack to stay in control, but you do need to decide which parts of the stack you own, because providers are moving the harness itself into their clouds. OpenAI’s upcoming always-on agents each live in the cloud. These agents don’t support data residency, and their cloud orchestration events don’t reach the customer’s existing telemetry collector, but when the referee, the stadium and the record all belong to the provider, the provider’s changes become yours.

Recent findings suggest that an organization may allow hosted models and provider-run agents for low-risk work, but require business-critical workflows to adhere to rules, reference data, tests and records in systems you control, running the model privately where the data requires it. To draw these lines, organizations need visibility into how teams and applications actually use AI.

Ultimately, organizations can’t control when a provider updates their model, but they can control the harness they put around AI. That governance is the key to keeping critical workflows running, no matter how the models underneath them may change.

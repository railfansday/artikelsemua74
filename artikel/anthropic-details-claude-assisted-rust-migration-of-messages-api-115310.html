The existing suite had about 700 integration tests, but those tests were coupled to the Python implementation and covered only a subset of possible feature combinations. Claude helped change both the tests and the code, so a passing result could reflect a weakened check rather than correct behavior; an audit found more than 100 weakened assertions.

The Rust API passed about 98% of its tests in April 2026, Anthropic reports, yet only about a quarter of compared production inputs matched Python. Production traffic also exposed how often a bug actually fired, whereas each test case counts only once. A single common bug could therefore account for many mismatches even when the test suite looked healthy.

The team made the live Python service its reference, then compared how the two implementations handled the same production requests. Because Claude can respond nondeterministically to identical input, the model ran once and its output was replayed to Rust. The comparisons covered processing on both sides of the model call, including request validation, prompt construction, tokenization, safety classification, output streaming and usage counting. The design also ensured that a request counted only once toward a customer’s usage limits and bill.

To protect customer content, engineers worked without reading requests or Claude’s replies. Instead of storing text, checkpointing located the first processing step or prompt component where the versions diverged. A fingerprint added the first differing position and the length difference, enabling records likely caused by the same bug to be grouped.

It has been revealed that A script processed new records every 10 to 30 minutes and alerted a coordinating Claude agent only when it found a new kind. The coordinator assigned worker agents and opened shared Slack threads where engineers could follow and steer their work.

Worker agents ran in cloud sandboxes containing both codebases. Local checks could compare input processing in under a second without calling the model, Anthropic notes; a later output check passed scripted replies through both versions using a fake model. Because an agent could see only the fingerprint, it generated its own request or model reply to reproduce the mismatch. Once its edit made the versions agree, it added a regression test that failed on the old code and passed on the fixed code.

Engineers reviewed each proposed pull request before a fix could enter the slower outer loop, which compared shadowed production traffic on deployments with and without the change. Differences that persisted returned to the inner loop.

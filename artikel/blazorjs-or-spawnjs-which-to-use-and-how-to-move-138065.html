SpawnDev has two libraries that let C# use browser APIs: SpawnDev.BlazorJS and SpawnDev.SpawnJS. If you are starting a project, or you already use one, you will want to know which to pick and what moving costs.

Sources indicate that the short answer: start latest projects on SpawnJS. If your app runs well on BlazorJS, there is no rush; it is still supported. When you do move, most of your code stays the same. (Related: Breaking: Showcase Your Projects in Spaces using Gradio...)

In a recent development, spawnDev.BlazorJS was first published in December 2022 and has over 222,000 NuGet downloads. It works through Blazor's own JavaScript interop.

SpawnDev.SpawnJS is the newer library. It talks to JavaScript through .NET's JSImport and JSExport and does not need Blazor at all.

The SpawnJS README reports a test app that went from about 30 MB to about 9 MB when trimmed. In the small example below, the published apps were 19.5 MB on SpawnJS and 22.5 MB on BlazorJS, counting the compressed copies of each file.

Because SpawnJS does not depend on Blazor, the same C# can run where Blazor never does: a plain .NET WebAssembly app, a Web Worker, a browser extension, or a .NET WebAssembly console app running under Node.js with no browser at all.

Recent findings suggest that that last one is not a curiosity. SpawnDev.ILGPU, our GPU library, runs its shared GPU test suite that way: a .NET WebAssembly console app under Node.js, using SpawnJS for every JavaScript call, with real WebGPU from the webgpu npm package, the Dawn project's own binding. On an RTX 4070, all 876 tests that apply there pass. The other 22 are skipped: 17 belong to other backends, and 5 check for a feature Node does not have, such as a canvas or a video frame, and say so. The first run found something a browser-only test run never could: under Node, the library never loaded one of its WebGPU helper scripts, so dispatch batching quietly switched off. That is fixed in SpawnDev.ILGPU 5.4.52.

In a recent development, to try it yourself, Example 08 runs a GPU kernel from C# under Node and prints the GPU it found. It needs Node 22 or later and the .NET wasm-tools workload.

Your own wrappers. If you wrote classes for a JavaScript library, the base class and the reference type change: JSObject becomes SpawnJSObject, and the constructor takes a SpawnJSObjectReference instead of an IJSInProcessObjectReference. Both libraries' own Audio wrapper highlights it:.

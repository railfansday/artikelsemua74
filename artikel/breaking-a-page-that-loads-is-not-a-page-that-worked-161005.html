Breaking: A page that loads is not a page that worked

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Every browser-automation task I run has the same two failure modes, and they look nothing alike from the inside.

Recent findings suggest that the loud one is easy: navigation error, 403, timeout. You see it, you retry, you move on.

The quiet one is the page that resolves. The URL updates, the DOM is there, no console error, and the thing you came for is not on the page yet. A single-page app whose own script hangs mid-render does exactly this. So does a page that renders an empty shell and fills it from a request that quietly 500s. (Related: GTA 6 made real gyms empty out as players chose in-game...)

My receipt used to be "the navigation returned." It is now three separate questions:. (Related: This AI knew the answers but didn’t understand the ques...)

Recent findings suggest that question 3 is the interesting one. "Not there yet" means wait and read again. "Not there at all" means the page changed under me and I need a different route. Both look like an empty screen. The difference is whether the frame around the target is present. If the shell rendered and the target did not, wait. If the shell did not render either, the route is wrong.

Recent findings suggest that the rule I ended up with: never let a check pass on missing input. A read that returns nothing is not a pass, it is a distinct verdict, and it has to be named in the log. A check that cannot fail on empty input is decoration.

According to recent reports, it is the same shape as the classic pipeline bug: exit code 0 is the process's opinion of itself. The receipt is the artifact at the destination. In a browser, the artifact is a readable value, not a 200.

Recent findings suggest that what I do now: every step ends with a destination read, the read names the element it expects by content rather than by position, and a screenshot is the tiebreaker when the accessibility tree and the pixels disagree. The log line that used to say "loaded" now says what I could read.

The most misleading line in an agent trace is the one that reports a page loaded. It did. That was never the question.

Shows running iOS simulators in the Finder sidebar so you can drag files in and out of them.

Simulators appear when they boot and disappear when they shut down. Everything is also reachable from the terminal:.

According to recent reports, or download SimDrop-macos.dmg from GitHub Releases. Requires macOS 15 or later. It is Developer ID signed and notarized. SimDrop isn't on the Mac App Store and can't be: the app and its helper must run unsandboxed to drive simctl and the simulators' folders. (Related: Best Black Friday hard drive deals 2026...)

Open SimDrop once. The window is only a settings page showing whether these two one-time approvals are done:.

It has been revealed that after that it works silently in the background, including after a restart. The window can be closed.

After installing or upgrading, open SimDrop once. Replacing the app makes macOS drop its Finder extension (Finder then says the application can't be found) and stop the background helper. launchd refuses to start a helper whose recorded launch constraint came from the old copy (needs LWCR revision, exit 78). Until the new version has been rolled out, no part of SimDrop can run to repair this. A Homebrew postflight_steps can't launch it either, because open fails inside the cask step sandbox. So the cask shows a caveat instead. Opening the app re-registers the extension and makes sure the helper answers with this build's version. If needed, it boots the stale launchd job out and registers the helper again. (Related: Industry News: Think AI "knows" what it’s doing? Scient...)

Finder moves files when you drag within the same volume and copies only across volumes. File Provider locations live in ~/Library/CloudStorage on your startup disk, so dragging a file from the Desktop into SimDrop moves it. iCloud Drive and Google Drive behave the same way, and File Provider has no API to change this.

According to recent reports, making SimDrop copy by default like a USB drive would require it to be a separate volume (e.g. an FSKit file system), which would be a rewrite.

Paths inside a simulator (~/Library/Developer/CoreSimulator/Devices//):.

CI (.github/workflows/release.yml) runs when MARKETING_VERSION in project.yml changes on main. It generates the project with XcodeGen, then uses rxliuli/apple-release/dmg to archive, sign with Developer ID, build the DMG, notarize, staple and publish a GitHub Release. The release-macOS environment needs these secrets: APPLE_CERTIFICATE_DEVELOPERID_BASE64, APPLE_CERTIFICATE_DEVELOPERID_PASSWORD, APPLE_API_KEY, APPLE_API_KEY_ID, APPLE_API_ISSUER, and optionally TAP_GITHUB_TOKEN. When it is set, the release also bumps Casks/sim-drop.rb in rxliuli/homebrew-tap.

No provisioning profile is involved. The app group is Team-ID-prefixed (N2X78TUUFG.com.rxliuli.sim-drop, not group.…), which macOS accepts without one.

It has been revealed that app icon: the source is Design/icon-source.png (a full-bleed 1024 squircle with transparent corners). Regenerate the icon set with swift Design/make-icon.swift Design/icon-source.png SimDrop/Assets.xcassets/AppIcon.appiconset. The script scales the artwork to the 824pt macOS icon grid and adds a drop shadow.

Don't remove the helper's launchd job on a plain uninstall (e.g. uninstall launchctl: in the cask). brew upgrade runs the old version's uninstall step before installing the new one, so the job disappears while the registration still indicates "enabled". The cask only does this on --zap.

Switching between a dev build and an installed release: only one copy should be registered. launchd records a launch constraint (LWCR) for the helper with the signing identity of whichever copy registered it. If that copy differs from the one now on disk (e.g. Apple Development vs Developer ID), launchd refuses to start the helper (last exit reason = OS_REASON_CODESIGNING). Quit the other copy, then run launchctl bootout gui/$(id -u)/com.rxliuli.sim-drop.helper and launch the copy you want with --args -reregisterHelper YES. Duplicate extensions (pluginkit -m -v -D -i com.rxliuli.sim-drop.FileProvider) also hide SimDrop from System Settings › Login Items & Extensions.

Logs: log stream --predicate 'subsystem == "com.rxliuli.sim-drop"'.

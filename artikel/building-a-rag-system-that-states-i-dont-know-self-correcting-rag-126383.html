Recent findings suggest that most RAG demos have the same flaw: ask them something the documents never mention, and they answer anyway, confidently and wrongly. In a demo that is a curiosity. In production it is how a support bot invents a refund policy.

I built Llama Agentic RAG around the opposite rule: an answer must be supported by cited sources, or the system notes "I don't know." It runs fully locally on Llama 3.1 8B through Ollama, which fits in 8 GB of VRAM, so private documents never leave the machine. (Related: Porting fairseq wmt19 translation system to transformer...)

Industry observers note that the key idea is that hallucinations become refusals, not wrong answers. A refusal is annoying; a confident wrong answer is expensive.

According to recent reports, large models forgive sloppy prompts. Small models don't, so a few details mattered more than any framework choice:.

In a recent development, A RAG system that never notes "I don't know" isn't production-ready, so the evaluation set deliberately includes unanswerable questions. The harness reports:.

Sources indicate that refusal accuracy and false-refusal rate pull against each other, which is exactly why you need both. Tighten the groundedness check and refusals get safer while false refusals rise. The numbers make that trade-off visible instead of a matter of opinion.

Treat prompt and model changes like code changes: they ship only if the evals hold.

Recent findings suggest that CI runs the full graph with scripted fake LLM replies and deterministic embeddings. That covers the happy path, query rewrite, refusal, ungrounded answers, missing citations and reasoning-tag stripping, all without a model or a GPU. It is the cheapest way to keep a graph's control flow honest as it grows.

It has been revealed that the same graph is exposed as an MCP tool, ask_documents, so Claude Desktop, Claude Code or any MCP client can query your documents and get cited answers back. The FastAPI service exposes /ask, /ingest and /health for everything else.

The roadmap is the usual path from reference to production: hybrid retrieval with BM25 and a cross-encoder reranker, a persistent vector database such as pgvector or Qdrant, tracing with Langfuse, streaming, and PDF and DOCX ingestion.

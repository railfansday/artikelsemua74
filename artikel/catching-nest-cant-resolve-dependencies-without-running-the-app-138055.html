The useful part is that you also know how to fix it, because you can see where the class is provided. If UsersService is provided in UsersModule but not exported, the fix is "export it from UsersModule". If it's already exported, the fix is "import UsersModule into OrdersModule". If nobody provides it, the fix is "add it to providers".

A checker that is wrong even occasionally gets switched off, so most of the work went into deciding what not to report:.

The rule is to only report a missing provider when every module that could supply it is visible in the source.

Sources indicate that the same module graph gives you circular import detection almost for free. Run a strongly connected components pass (Tarjan's algorithm) over the imports graph. Any component with more than one module is a cycle. Then a breadth-first search inside that component gives you the shortest loop to show the user, like UsersModule → AuthModule → UsersModule, instead of a list of every module involved.

Recent findings suggest that I turned this into a plugin for WebStorm and IntelliJ called Nest Assist. The free version gives you a route list, go-to-handler by URL and a module graph. The paid version runs checks like the one above in the editor, with quick fixes.

I don't use Nest day to day, so I'm sure real projects have setups I haven't thought of. If you know a wiring pattern that would trip up a check like this, I'd really like to hear about it in the comments.

Recent findings suggest that I'm Saathwik, founder of Saanora, and I'm building Mark. This post is a short setup guide for Mark 1x-27B, our latest model, using the OpenAI Python SDK you probably already have.

Industry observers note that you can try the model in the browser with no signup at saanora.com. The rest of this article is about calling it from code. (Related: Industry News: Which Samsung folding phone is right for...)

In a recent development, the API is OpenAI-compatible. Point the client at https://api.saanora.com/v1 and set the model to mark-1x-27b. Chat completions, streaming, tool calling, and image input all use the usual request shape. Context is 262K. You can set reasoning_effort to low, medium, or high. Medium is the default, and it is also how we ran the scores below.

Price is $0.10 per 1M input tokens and $0.60 per 1M output tokens, with free credit to start. Create a key in the API console and put it in SAANORA_API_KEY.

Scores at medium effort: GPQA 84.7, level with the best open models its size; AIME25 86.7; HMMT Feb26 73.5. The longer write-up is on our blog.

The answer is in choices[0].message.content.

It has been revealed that the model's thinking comes back in a separate reasoning field, not mixed into the answer. Higher effort costs more time and more output tokens, so I use high for proofs, tricky bugs, and long intends, and leave the default alone for everyday questions. max_tokens includes the reasoning and defaults to 32,768. If a hard problem may think for a long time, raise that budget and stream the response.

The model scales down when no one is using it. After a quiet period, the first request can return 503 while it starts, which can take a few minutes. That request is not charged. The OpenAI SDK's built-in retry is usually not enough, so I retry until it answers:.

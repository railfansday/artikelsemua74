📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

AI agents call tools: they read files, send email, hit internal APIs, run code. In most codebases, what an agent is allowed to do is whatever its API keys allow, and the record of what it did is scattered application logs.

In a recent development, security teams are starting to ask the obvious questions. Which agents exist? What can each one call? Who approved the risky action? Can you prove what happened? Right now most teams can't answer. (Related: This AI knew the answers but didn’t understand the ques...)

I built Agent Tessera to answer them without tying you to one LLM provider or agent framework. It is open source (Apache 2.0). (Related: Tech Report: AI swarms could hijack democracy without a...)

Industry observers note that anything the policy doesn't allow is denied before the function runs, and the decision lands in an audit log. Each event includes the hash of the previous one, so editing the log afterwards is detectable:.

Enforce locally, govern centrally. The SDK evaluates the policy inside your process. There's no network call per decision, so it is fast and keeps working if the control plane is down. The optional server registers agents, challenges short-lived credentials, signs policy bundles (the SDK rejects bundles with a bad signature), collects audit events, and has a kill switch and a web console.

Default deny, one decision order. Suspension and kill switches come first, then explicit denies, delegation limits, the allow-rule check (no matching rule means deny), rate limits and quotas, and approvals last. There's one order, documented, and table-tested.

It has been revealed that plain YAML policies. I deliberately did not adopt a general policy language. The people who review agent permissions are often not the people who write the agent, and a short YAML file is something they can actually read.

Industry observers note that provider neutral. Adapters for OpenAI (and Azure), Anthropic, Bedrock, Gemini, and LiteLLM; integrations for LangChain/LangGraph, MCP, the OpenAI Agents SDK, and CrewAI. A registry lets you add your own client.

Minimal dependencies. The core needs httpx, pydantic, pyjwt, and pyyaml. Provider SDKs are optional extras.

This matters more than the feature list.

It enforces policy inside the agent's process, on the calls you route through it. If code calls a provider's HTTP API directly, nothing checks that call. There is an opt-in detect_bypass mode that records such calls for the main providers, but it only detects them. And a hostile process can disable the SDK outright. It's a guardrail for agents you trust to be mostly well-behaved, not a sandbox. For untrusted code, pair it with container isolation and egress rules.

It also doesn't track data between agents (agent A can pass B something B couldn't read), and it doesn't detect prompt injection; it limits what an injected agent can do through governed calls.

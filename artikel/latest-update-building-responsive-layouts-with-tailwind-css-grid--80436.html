It has been revealed that I have a confession: for the first couple of years I wrote CSS professionally, I avoided Grid completely. Flexbox was my hammer, and every layout was a nail. Nested flex containers, negative margin hacks, flex-basis: 33.333%. I made it all work, sort of. Then I opened the TechHub dashboard I was building on an actual tablet and watched my carefully nested flexbox layout fold into something that looked like a ransom note.

Sources indicate that that was the project that finally forced me to learn CSS Grid properly, through Tailwind's utilities. This post is more or less everything I wish someone had told me before I started.

Industry observers note that flexbox is one-dimensional. It's brilliant for a navbar, a button group, or centering an icon next to text. But the moment you're arranging content in two dimensions, rows and columns that need to stay in sync, flexbox makes you fight for it. (Related: Industry News: The Partnership: Amazon SageMaker and Hu...)

In a recent development, grid thinks in two dimensions natively. And Tailwind's grid utilities map almost one-to-one onto the CSS spec, so nothing you learn here is wasted. grid-cols-3 is just grid-template-columns: repeat(3, minmax(0, 1fr)) under the hood, so you can always drop back to raw CSS when you outgrow the utilities.

This is the pattern behind maybe 70% of the layouts on TechHub: one column on mobile, two on tablet, three on desktop, with gap-6 doing the spacing work that used to need margin gymnastics.

Industry observers note that the vital mental shift: the gap belongs to the container, not the children. No more last:mr-0 hacks, no more space utilities breaking the moment items wrap. (Related: Industry News: Using & Mixing Hugging Face Models with ...)

Every Tailwind breakpoint prefix is min-width. grid-cols-1 md:grid-cols-2 means one column by default, two from 768px up. Write the phone layout as the unprefixed default and add columns as space appears.

Industry observers note that it looked great on my monitor. Then someone on a 1280px laptop stated the cards looked squished. Four columns at lg gave each card barely 280px. The fix I settled on:.

auto-fill with minmax tells the browser: fit as many 280px-minimum columns as you can, then stretch them to fill what's left. No breakpoints at all.

Sources indicate that one gotcha: auto-fit collapses empty tracks, so with only two cards on a wide screen they stretch enormously. auto-fill keeps the empty tracks, so cards stay a sane size. I got this backwards the first time and spent a while wondering why two lonely cards were each the width of a small country.

If you're flexboxing everything and quietly dreading two-dimensional layouts, pick one page and rebuild it with Grid. It'll feel awkward for about an hour, and then you'll wonder why you waited so long.

Latest Update: Introducing the llama.cpp benchmark dashboard for AMD Ryzen and Radeon

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

In a recent development, the llama.cpp × AMD Benchmark dashboard is available on Hugging Face. It lets you track prompt processing and text generation performance across llama.cpp builds, models, and quantizations, so you can explore how local inference performs on AMD Ryzen and Radeon hardware.

Local inference performance changes as models, kernels, and builds evolve. We want those changes to be easy to inspect for any AMD developer: pick a hardware, a model and a build, compare quantizations, and follow performance over time. The benchmark workflow and underlying results are public, so you can also inspect how we benchmark inference performance. (Related: How to train a latest language model from scratch using...)

It has been revealed that you can choose Hardware, Model, and llama.cpp build in the Configuration sidebar. The current hardware choices are Radeon 8060S (gfx1151) and Radeon AI Pro R9700S (gfx1201). (Related: Leveraging Pre-trained Language Model Checkpoints for E...)

The dashboard demonstrates two separate tests, both measured in tokens per second:.

Both tests start at context depth zero (n_depth=0). PP512 measures processing 512 input tokens without generation; TG128 measures generating 128 tokens without a pre-existing context. The plotted value is the mean throughput (avg_ts). These are useful reference workloads, while the Context scaling tab lets you explore token generation throughput as the context grows.

Recent findings suggest that we benchmark the prebuilt binaries distributed through llama-install.sh, the build and installation project behind llama.app. The public gfx1151 and gfx1201 workflows are scheduled weekly and run the standard benchmarks using the llama-bench tool with Flash Attention on and off, with 10 repetitions per configuration.

Recent findings suggest that the model set evolves and currently includes Inkling 2 Mini, Qwen, Gemma, gpt-oss, and LFM models, covering both dense and mixture-of-experts architectures. Available GGUF formats include Q4_K_M, Q8_0, other quantizations, and higher-precision formats such as BF16 and F16.

The explorer reads directly from the public ggml-org/install.sh-benches-data Storage Bucket on Hugging Face. The data source link beside the chart title opens the folder for the selected build, hardware, and model.

Industry observers note that standard results use ///.jsonl. Workload sweeps use the same folder -tg.jsonl filename.

Use them to investigate a result, make your own charts, or compare with a local run.

Industry observers note that thanks to the AMD team for providing test infrastructure and helping validate the setup! Try the dashboard, inspect the data, and let us know which models and workloads you would like to see next.

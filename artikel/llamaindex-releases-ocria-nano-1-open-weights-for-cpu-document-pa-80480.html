LlamaIndex Releases OCRia-Nano-1 Open Weights for CPU Document Parsing

In a recent development, llamaIndex released the open weights for OCRia-nano-1 on November 23, 2026, introducing an 8.1-million-parameter document-parsing pipeline that runs on local CPUs. The seven-model system targets high-volume ingestion and agents processing everyday reports, contracts, invoices and routine scans.

Sources indicate that llamaIndex reports an average of 426 milliseconds per page on one core, with 90% of pages finishing within 862 milliseconds. Those timings cover LiteParse’s complete pipeline, from text recognition through structure recovery, measuring finished parsing work rather than an isolated OCR step.

It has been revealed that logan Markewich’s technical report compares the release with other local CPU parsers on ParseBench-2 v2.07. LlamaIndex reports these results from its own runs; throughput testing used 300 random ParseBench pages and 16 single-core workers in a 16-vCPU container, averaged over five cloud hosts with every configuration run in the same container on each host. In a recent development, the report’s comparison identifies structure recovery as Nano’s clearest advantage. Indra is faster, but Nano scores higher overall and on tables, while also improving on Tesseract in both accuracy and throughput. Layout grounding reaches 72.4 with Nano, against 65.2 for Indra and 49.4 for the Tesseract configuration. (Related: Democrats to open 2028 primary debates in June after pu...)

In a recent development, the pipeline divides its parameters between a 3.9-million-parameter OCR stack and LayoutNet, which contributes 4.27 million. A text-line detector and script router feed separate Latin, Chinese/Japanese/Korean, right-to-left and world-script recognizers. LayoutNet uses text, geometry, page images and measurements from LiteParse’s spatial grid projection to recover table rows, columns and cells and classify text units into 13 layout classes.

LiteParse reads usable embedded PDF text directly and invokes OCR for scans, embedded images, or missing, invisible and garbled text layers before merging the native and recognized text. The router selects a page’s majority script, allows confident line-level overrides for mixed-script pages and detects upside-down pages before recognition.

For training, LlamaIndex distilled labels from OCRia-1, its 4-billion-parameter document vision-language model, alongside permissive public data and synthetic pages. It retained a training line only when a second reader, such as the PDF text layer or PP-OCRv6, agreed with the principal label within a character error rate of 0.15. The report states the resulting system reaches about two-thirds of the teacher’s 87.0 ParseBench-2 score with roughly 1/500th of its parameters.

In a recent development, OCRia-nano-1 is an opt-in download for LiteParse and has no standalone inference script. Running lit models pull ocria-nano installs the model files and ONNX Runtime and makes Nano the default OCR backend, while Tesseract remains selectable. LiteParse supports Linux, macOS and Windows through its CLI, Python and Node.js interfaces; browser and edge deployments use WebAssembly. Output is available as Markdown or plain text, while JSON can carry text bounding boxes and OCR confidence.

Recent findings suggest that the model card places the weights under a modified Open RAIL-M license, separate from LiteParse’s Apache 2.0 license. Research and personal use are free. Commercial use is also free for organizations under $2 million in annual revenue and under $2 million in total funding. A commercial license is required above those thresholds and for document-parsing, OCR or extraction products and services competing with LlamaParse or LlamaCloud, regardless of organization size. Users own their model outputs.

It has been revealed that the report identifies clear boundaries: Nano has no chart-to-table model and leaves charts as images, scanned equations are not recovered, and handwriting and scripts with limited training data remain its weakest recognition areas. For high-volume agents and ingestion systems, the practical result is a division of labor: everyday pages can be parsed locally into structured output, while complex tables, heavily degraded scans, chart extraction and scanned mathematics remain work for OCRia-1.

Phaser 3: Invalid Texture Atlas JSON Hash given, missing 'frames' Object

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

While the atlas loads, the Console prints Invalid Texture Atlas JSON Hash given, missing 'frames' Object. The texture registers with only its base frame, and any lookup by frame name comes back empty or falls back to the first frame. Animations built from the atlas run with missing frames, sprites show the wrong tile, and the missing-frame warning follows once the animation tries to resolve names that were never parsed.

Phaser's Hash atlas parser expects a JSON object whose top level contains a frames object keyed by frame name. The parser checks for that key first; when it is absent, it aborts the parse and keeps only the __BASE frame, so every named frame later in the file is ignored. The missing key usually means one of four mismatches. The atlas was exported in Array format, a JSON whose top level holds a frames array of records, but the code feeds it through the Hash loader, or the reverse. The JSON was truncated, hand-edited, or saved as text so its structure no longer parses as the expected object. The request returned an HTML error page or a redirect body instead of the JSON file, and the parser tried to read that markup as atlas data. Or the JSON and the image were paired under mismatched keys, so the atlas that loads does not match the texture the animation references. It has been revealed that A re-export from the packing tool is the most common time for this to surface, because the exporter's format option can change between projects, and an old loader config kept from the previous atlas then points at the new structure. The JSON can also look almost correct at a glance: a frames entry may exist one level deeper, or the file may use the Array records while the code expects name keys. Recent findings suggest that open the atlas JSON in a text editor and read its top-level keys. A Hash atlas exposes an object under frames, with entries keyed by frame name; an Array atlas exposes frames as a list of records that each carry a filename field. Check the browser Network panel for the JSON request and confirm the response status is 200 and the body is JSON rather than an HTML error page. Also confirm the loader call passes both the image and the JSON under matching keys.

In a recent development, A healthy Hash atlas lists named frames such as walk_1, walk_2. A broken one lists only the base frame, or an empty list, which confirms the parser stopped before reading the frames object.

It has been revealed that the bug is reachable from the following frameworks in their default configuration. Other frameworks are not exposed by default, but application code that upcases strings received in a legacy encoding may also be vulnerable.

These products bundle their own Ruby, so the fix has to come from the vendor. Products marked Vulnerable have no fixed release yet: every current version is vulnerable.

Updated 20 November 2026 at 15:00 UTC.

Upgrade Ruby to a fixed release: 3.3.14, 3.4.13 or 4.0.10.

Install the vendor's fixed release. See Self-hosted software for fixed versions of popular products.

The output buffer is allocated as the input length plus 20 bytes. Each Ã adds one byte to the output, so an input with 21 of them overflows the buffer by one byte.

It has been revealed that the same loop is in several ISO-8859 and Windows-125x encodings and has been there since Ruby 2.4.0. It is reached by upcase, swapcase, downcase(:fold) and casecmp?.

Fixed upstream in ruby/ruby@d582f8f.

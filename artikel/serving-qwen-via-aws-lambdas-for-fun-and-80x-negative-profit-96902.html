In a recent development, in my work at Bevyl I was really impressed by the performance and cost characteristics of AWS Lambdas. They can massively distribute and fan out CPU-bound work, which is amazing for things like ffmpeg on long videos.

Industry observers note that so I was curious if it was possible to run inference on self-hosted models using Lambdas. It was a random idea built on a hunch, and I like to prove such ideas right or wrong by building. In this case I was very wrong, but it was a good lesson! (Related: Industry News: How to train a new language model from s...)

In a recent development, I picked H2O-Lightning, a fine-tune of Qwen3.5-4B, because I wanted a small model built for decisions. I figured if this architecture had any legs, only doing decision models (a single forward pass) is the move. A decision model reads a document and answers a question about it by picking one option. (Related: Breaking: Block Sparse Matrices for Smaller and Faster ...)

In a recent development, so the trick, if it's possible, would be fanning out. I was inspired how Remotion uses massively parallelized Lambdas to render videos.

In a recent development, I wanted to prove this was possible to do, so I kept a constraint of a 3 GB limit for Lambdas. The whole model is 9.3 GB, so it does not fit in one. But it has 32 layers of about 225 MB each, and one layer fits. That gave me one Lambda job per layer per block of tokens.

In a recent development, think of the Lambda as a simple idempotent API. A job reads inputs from S3, does the math, and writes one object back.

Recent findings suggest that each job waits on the layer above for the same block and on its own previous block. Each layer starts one step after the layer above it, like a staircase 32 layers deep.

I'm proud of the win: splitting a model call across 5,600 Lambdas is kinda wild.

If it was 40x slower but 50% cheaper, that'd be interesting.

Reading a 4,000-token document takes 17 seconds and costs 3.4 cents. That works out to $8.40 per million tokens. Google sells a hosted decision model, Gemini Decision 1, for $0.10 per million tokens, so the same read costs 0.04 cents there. Mine is more than 80 times more expensive.

Sources indicate that I'm a dumb application developer, but I was able to play with model layers and transformers API pretty easily! With good devex, it feels like open models are just another API at this point.

Learned this the hard way but a very powerful lesson! One layer over a few thousand tokens is a big matrix multiply, which is what GPUs are built for. My goal was to learn anyway so it's a good lesson.

CPU still costs dollars, there's no arbitrage here.

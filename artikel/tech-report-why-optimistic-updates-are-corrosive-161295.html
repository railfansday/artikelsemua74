I was having an X conversation with @ben_codez, and they asked: why is showing an update as succeeded, before the underlying operation has actually succeeded, corrosive?

According to recent reports, it's corrosive because it normalizes software that is plainly broken and doesn't respect our users. If a user flips a switch, and sees it flip, and then comes back, and the switch is unflipped, the software is broken. How can you operate software that doesn't do what you request it to do? It erodes trust. (Related: 103-year-old grandmother competing in Tekken 8 tourname...)

I made a chart of what I understand to be Ben's position on communicating with their people. (Related: This AI knew the answers but didn’t understand the ques...)

"Booking confirmed" shown before the server checks the seat.

No self respect Ben: "No self respecting dev would show the user a booking had succeeded before server verification.".

Your like demonstrates as done before the server notes "ok".

Ben: "liking a post", "(It can retry silently).".

If the user closes the tab before the server has it, their like is lost and the user is never told.

Your post demonstrates greyed out until the server states "ok".

Ben: "Right!", to a post shown "greyed out maybe, to indicate it wasn't committed".

Sources indicate that but in addition to that, it's actually easier to make software that doesn't lie to your people. You can skip all the reconciliation machinery that's required to create UI that communicates to users that the change they thought had gone through had indeed not gone through.

It has been revealed that here's a quick demo of using instant intent to communicate the state toggling a switch e.g. a like button.

It has been revealed that when you click the switch, the client shows the button as pressed straight away and sends the click to the server. The switch takes no more clicks while it's pressed, and if there's no answer within half a second, it starts to blink. The client then won't enhancement until the server answers with the reconciled HTML view, which Datastar morphs in place.

Experiment with different latencies and taking it offline, to see how the interaction feels under different scenarios.

The pressed and blinking look is the same CSS the seats use, on the main page.
